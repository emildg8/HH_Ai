## Какие должности подходят (техническая линза)

### Приоритет 1 — активная охота

- DevOps / SRE **junior+ → middle** (удалёнка)
- Системный инженер, инженер инфраструктуры, observability
- Linux DevOps, инженер CI/CD

**Ограничение:** JD с обязательным K8s/Terraform/GitLab 3+ года — разрыв стека; не массовая серия.

### Приоритет 2 — параллельно, отдельное резюме и письмо

- L2/L3 техническая поддержка (банк, финтех, highload)
- Application support L2+

### Приоритет 3 — точечно

- TAM (эскалации, enterprise)
- Руководитель службы поддержки (риск R3 overqualified в авто-серии)

### Вне профиля (ручной контур / не гнать)

DBA, DevSecOps без evidence, Senior/Lead DevOps, чистый разработчик, K8s-platform без коммерции, Data Engineer.

## Маршруты охоты — достаточно четырёх

Четыре трека в [`config/hunt-tracks.json`](../config/hunt-tracks.json) **покрывают** все рекомендованные роли. Пятый маршрут не нужен.

| Рекомендация | Маршрут | R-tier | Серия | Point apply |
|--------------|---------|--------|-------|-------------|
| DevOps / SRE / CI/CD | `devops` | R0 | авто P1 | **auto** HT.7.1, 1–2/день |
| Системный / infra / cloud / observability | `infra` | R1 | авто P2 | **auto** HT.7.2 ✅ |
| L2/L3 финтех | `l2l3` | R2 | авто P3 | **auto** HT.7.4 (как devops/infra) |
| TAM | `tam` | R2 | approval P3 | **auto_with_approval** |

По умолчанию активны **`devops` + `infra` + `l2l3`** (`defaultActiveTracks`). `l2l3` — auto без `userApproved`; `tam` — дашборд / approval; **`devops:apply-point-ready --track=tam`** только с approval.

**Нюанс:** заголовки с «руководитель» / lead могут уйти в **R3** (`isClearlyOverqualifiedTitle`) — вне авто-серии; точечные отклики с approval.

Резюме на hh: [`config/resume-routing.json`](../config/resume-routing.json) — devops, support, support_lead, tam, data (data вне охоты).

Рекрутер / ATS **не видит** pet и GitHub. Смотрит: заголовок → последнее место → ключевые слова → вилка ЗП → «О себе».

### Снимок hh (июнь 2026)

| Сигнал | Как читает HR | Оценка |
|--------|----------------|--------|
| Заголовок «Технический эксперт L2» | Поддержка 2-й линии, не DevOps | Для DevOps-JD — mismatch |
| Текущий опыт СБП | Банк, инциденты, алерты | Сильный **L2+ финтех** |
| Softline, FBD | В снимках резюме слабо | Потеря ~50% истории |
| Блок skills | Почти пуст (в снимках) | Провал ATS по Docker/K8s/CI/CD |
| Pet (HH Ai) | Не в резюме | Для HR = 0 |
| 14+ лет | Зрелый специалист | L2 — «дорого»; DevOps — «где стек?» |

**Вердикт HR:** опытный **инженер эксплуатации / L2 в банке**; на DevOps middle — сомнительно **без перепаковки CV**; на L2/L3 финтех — **зовите на скрининг**.

Согласуется с данными проекта: 42 declined, 48 viewed; главная причина на DevOps-JD — резюме/письма как L2 ([`HUNT-TRACKS-ROADMAP.md`](HUNT-TRACKS-ROADMAP.md) §29.06).

|-------|----------|------------------|

## Должности по tier HR (прохождение скрининга)

### Tier A — высокий match на бумаге

1. Инженер / специалист технической поддержки **L2, L3** (банк, платёжки, highload)
2. Ведущий прикладной администратор / application support L2+
3. Инженер технической поддержки **Linux** (2 линия)

### Tier B — после перепаковки CV (3–4 блока задач, см. MARKET-RU-HR-QA)

4. Системный инженер (Linux, мониторинг)
5. Инженер инфраструктуры
6. DevOps-инженер junior+ / middle (точечно, не массово)

### Tier C — точечно

7. Руководитель службы поддержки  
8. TAM (технический, не sales)

### Tier D — HR отсечёт

DevOps с K8s 3+ года, DevSecOps, DBA, Senior/Lead, разработчик, Data Engineer.

### Блоки задач для DevOps-JD (язык рынка)

| Блок | Примеры формулировок |
|------|---------------------|
| CI/CD и релизы | GitLab CI, pipeline, rollback (честно: pet + командная автоматизация в банке) |
| Контейнеры | Docker (E2); K8s — только если в JD и на собесе |
| Наблюдаемость | Grafana, алерты, метрики, Kibana |
| Инциденты | on-call L2, runbooks, −15% MTTR, эскалации |

## Зарплата — рынок РФ 2026 (на руки, удалёнка)

Контекст: рынок перегрет на **входе**; бум ЗП охладился; вилка в JD должна совпадать **до** отклика ([`MARKET-RU-HR-QA.md`](MARKET-RU-HR-QA.md) §6).

### Ориентиры рынка (внешние + проект)

| Роль | Медиана / типичная вилка |
|------|--------------------------|
| L2/L3 support | ~120k медиана; 90–200k; с банком/опытом — верх |
| System / infra engineer | ~165–235k (middle) |
| DevOps middle remote | ~180–220k медиана; 150–300k |
| DevOps + K8s/cloud | +20–40% к базе (пока не ценовой сегмент без evidence) |
| Руководитель ТП | 220–320k |

Источники: TalentScan, JHunt, SkillStat, quick-offer.ru/hh — см. ссылки в MARKET-RU-HR-QA.

### Три цифры для партнёра (рекомендация сессии 29.06)

#### DevOps / infra (основная стратегия)

| | Сумма ₽ на руки | Комментарий |
|---|-----------------|-------------|
| **Минимум** | 190 000 | Ниже — продаём 14 лет как junior+ |
| **Комфорт** | 220 000 | Середина middle− / strong junior+ + банк |
| **Мечта** | 250–280 000 | Банк/финтех + сильный техсобес + pet |

В поле hh для DevOps-JD: **200 000–240 000** (диапазон, не одна цифра).

#### L2/L3 (запасной канал, выше конверсия)

| | Сумма | Комментарий |
|---|-------|-------------|
| **Минимум** | 170 000 | Быстрый оффер |
| **Комфорт** | 200 000 | Банк + метрики + 14 лет |
| **Мечта** | 230 000 | L3 / ведущий / on-call premium |

На L2-JD 200k — верх рынка; HR может отсечь как «дорого для L2». Тактика: **разные вилки под роль** (L2: 180–220, DevOps: 200–240).

#### Руководитель поддержки

Комфорт **220–280k**; 300k+ — крупный аутсорс/банк.

### Связь с настройками

[`config/preferences.json`](../config/preferences.json): `minMonthlyRub` / `targetMonthlyRub` = **200 000**, `maxMonthlyRubSearch` = **300 000** — адекватный **пол** для DevOps/infra; для чистого L2-JD завышен без обоснования title «ведущий» / L3.

### Переговоры (кратко)

1. На скрининге HR: «Комфорт 220, от 200 при сильном проекте и удалёнке».
2. На финале с техлидом: блоки задач, не «14 лет»; pet — одна фраза на собесе.
3. Банк/СБП — премия +10–15% в торге.
4. Не целиться в 280k DevOps без K8s в CV — фильтр отсечёт раньше человека.
