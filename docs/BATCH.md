# Массовый отклик (batch)

**Версия:** 2.0.1

Батч по очереди запускает `hh-apply-chat-letter.mjs` для каждой вакансии с утверждённым письмом (Playwright, одна вакансия за раз).

## Запуск

```bash
# из терминала (профиль DevOps)
npm run devops:apply-batch

# или с лимитами
node scripts/hh-apply-batch.mjs --min-score=50 --limit=20 --batch-scope=noQuestionnaire
```

Из **дашборда**: кнопка батча + выбор области (см. [DASHBOARD.md](DASHBOARD.md)).

Переменная `HH_BATCH=1` выставляется автоматически; быстрый режим — `HH_FAST=1` (по умолчанию в батче).

## Области (`batch-scope`)

| Область | Поведение |
|---------|-----------|
| `noQuestionnaire` | **Рекомендуется для массового отклика.** Анкета на hh.ru → отклик не отправляется, вопросы в карточку, батч идёт дальше |
| `queue` | Вся очередь, включая вакансии с пометкой «вероятная анкета» |
| `questionnaire` | Только карточки с анкетой (дозаполнение и ручной/точечный отклик) |
| `hidden` | Скрытые по фильтрам ролей |

Код: `lib/batch-scope.mjs`.

## Анкета работодателя

Если на форме отклика обнаружена анкета:

1. Вопросы собираются (`collectBestQuestionnaire`) и сохраняются в запись очереди.
2. Отклик **не отправляется**.
3. Скрипт завершается с кодом **`5`** (`HH_APPLY_EXIT_QUESTIONNAIRE_DEFERRED`).
4. Лимиты откликов за **час/день** (`lib/hh-apply-rate.mjs`) **не** увеличиваются.
5. В дашборде карточка в разделе **«Анкета»**.

Дальше: заполнить ответы в дашборде → **Сохранить** → отклик с карточки или вручную на hh.ru.

## Журнал пропусков (2.0)

В `data/hh-apply-chat.log` и консоли батча — короткие причины, например:

```
[batch] Пропуск 8/26: не выбрано резюме «DevOps» — «Senior SRE»
[batch] Пропуск 5/26: анкета: 20 вопр. — «SDET …»
[batch] OK 3/26: Platform Engineer
```

Технически: маркер `[hh-apply-batch-skip]` в логе дочернего процесса (`lib/batch-skip-reason.mjs`).

## Резюме в форме

Обязательно в профиле:

```env
HH_PROFILE_RESUME_TITLE=DevOps
HH_PROFILE_RESUME_HASH=...   # из npm run devops:list-resumes
```

Без hash скрипт пытается выбрать резюме по подстроке в названии на hh.ru.

## Управление во время батча

Файл `data/batch-control.json`: пауза, стоп, продолжить — кнопки в дашборде.

Прогресс: `data/batch-progress.json`, `data/apply-chat-progress.json`.

## Лимиты

Настраиваются через env (см. [CONFIG.md](CONFIG.md)) и отображаются в дашборде. Успешный отклик записывается в `data/hh-apply-launches.json` (не в git).

## Типичные пропуски

| Сообщение | Действие |
|-----------|----------|
| `не выбрано резюме «…»` | `devops:list-resumes`, обновить hash/title |
| `анкета: N вопр.` | Раздел «Анкета», не ждать отправки в батче |
| `вакансия недоступна` | Архив / снята с публикации — пропуск нормален |
| `нужен вход` | `npm run login` |
| `капча` | Решить в окне Chromium или `HH_HEADLESS=0` |
