# Очередь и отклики — подводные камни

Кратко для эксплуатации HH Ai (дашборд + батч).

## Статусы карточки

| Статус | Смысл |
|--------|--------|
| `pending` / `approved` | Активная очередь — батч и вкладки «Очередь» / «Без анкет» |
| `responded` | Отклик уже на hh.ru (или наш) — **батч не трогает**, карточка во вкладке **«Отклики»** |
| `rejected` / `approved` (решение) | Ручная разметка «подходит / нет» |

## Типичные ловушки

1. **«Уже откликнулись», а скрипт ищет DevOps** — на странице `vacancy_response` hh.ru показывает старое резюме (Data Engineer), нужного нет в списке. Это не баг роутинга: повторный отклик закрыт. Скрипт должен писать **«уже отклик на hh.ru»** и уводить карточку в `responded`.

2. **Много вкладок Chromium** — один профиль Playwright; батч закрывает лишние вкладки в начале каждого отклика. Не запускайте параллельно harvest + батч без необходимости.

3. **Очередь ≠ только UI** — даже если карточка скрыта фильтром, в JSON она могла оставаться `pending`. Команда и кнопка **«Убрать с откликом из очереди»** ставят `responded`.

4. **Резюме не в списке работодателя** — иногда это следствие п.1 (отклик уже был). Перед ошибкой скрипт повторно проверяет статус страницы.

5. **Батч `--resume`** — продолжает по `processedIds`; карточки с `responded` в кандидаты не попадают.

## Команды (меньше ручного труда)

```powershell
npm run devops:prune-responded-queue          # убрать из активной очереди все с откликом
npm run devops:prune-responded-queue -- --dry-run
npm run devops:probe-vacancy-state -- --id=<uuid> --write   # прочитать статус с hh.ru в карточку
npm run devops:apply-batch -- --resume
```

Батч **сам** в начале/конце прогона вызывает prune для карточек с откликом.

## Резюме в форме отклика

hh.ru **сам фильтрует** список резюме под вакансию. Config (`resume-routing.json`) задаёт **желательную** роль (DevOps / Data / поддержка), но скрипт выбирает только из того, что видно на странице.

1. Читает `[data-qa="resume-select-item"]` + radio.
2. Сопоставляет с `titleOnHh` / `titleMatch` / `hash` из config.
3. Если DevOps нет в списке, но есть Data — может взять Data с пометкой в логе (не ошибка роутинга).

Диагностика:

```powershell
npm run devops:list-resumes
npm run devops:preview-resume-routing
npm run devops:probe-response-resumes -- --id=<uuid>
```

## Что по-прежнему вручную

- `npm run login` при сбросе сессии / капче
- Анкеты работодателя (раздел «Анкета») — батч пропускает с кодом 5
- Отклик на вакансии, где hh.ru **никогда** не предлагает нужное резюме (первый отклик другим CV)

См. [ROADMAP.md](ROADMAP.md) (R2.x — invited в эталоны писем, метрики).

## Качество писем перед батчем

Утверждённое сопроводительное проверяется правилами (`lib/letter-quality.mjs`). В дашборде: сайдбар **«Письма»**, precheck серии, оценка **0–10** на карточке. Подробно: [COVER-LETTER-PLAN.md](COVER-LETTER-PLAN.md), [BATCH.md](BATCH.md).

```bash
npm run quality:check
npm run devops:regenerate-letters -- --only-fail --limit=30
```
